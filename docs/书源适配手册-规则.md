# 轻阅 Lite · 书源适配手册（适配哪些规则）

> 面向对象：给轻阅 Lite（柴阅引擎）写/改书源的人
> 引擎：**柴阅/Chaiyue**（`ReaderModels` + `RuleEngine` + `ReaderPlatform`，vendor 在 `LegadoEngine/Sources/Chaiyue*`）
> 语义：Legado 3.0

## 0. 一页速查：书源 JSON 的每个字段，谁负责、怎么写

| 字段 | 谁来求值 | 适配要点 |
|---|---|---|
| `header` | 引擎 | 可 `@js:` 求值；**UA 要移动端**（有些站桌面 UA 给另一个页面 ⇒ 0 本）⭐ |

| `ruleBookInfo` | 引擎 | `name`/`author`/`intro`/`coverUrl`/`kind`/`lastChapter`/`wordCount`/`tocUrl` |

| `ruleContent` | 引擎 | `content`（+ `imageStyle`）|

## 1. 三条硬规则（不满足就必然出问题）

### ⭐⭐⭐ 规则 1：大段 JS 放 `jsLib`，规则里留薄壳（**软建议，不是轻阅的硬限制**）

⚠️⚠️ **口径更正（2026-11-23 实测）**：轻阅宿主**代码里没有单条规则长度上限**
（`grep 8192/16384/maxRule` 在 `QiReaderLite/` 与 `LegadoEngine/` 全仓**零命中**）⭐⭐⭐
⇒ ⇒ **「8192」是别的宿主（安卓 Legado / 栖阅 WebView）的限制**，**轻阅不受此限** ⭐⭐⭐
⇒ ⇒ **书山聚合 v6 的 `exploreUrl` 有 10240 字符、`ruleContent.content` 有 11080 字符、`jsLib` 有 84KB
   ⇒ 在轻阅里能原样跑**（CI 真引擎实测通过）** ⇒ ⇒ **不必为了迁就轻阅而 slim 化** ⭐⭐⭐

✅ **但仍建议 slim 化**（三个理由，与长度上限无关）：
1. **可读性**：规则字段里塞 80 KB JS ⇒ 没人能维护
2. **可移植**：换宿主（安卓 / 栖阅）时会被 8192 卡住
3. **单条规则失败 = 整条链死**：薄壳一旦抛错，字段整片为空 ⭐⭐⭐

**写法示例**：

```js
// jsLib 顶层（一条 BODY 字面体）
var nhSlim_nh_exploreUrl_BODY = "…完整 JS…";

// 规则字段（薄壳）
@js:
var __out = nhSlim_nh_exploreUrl.call(this,
  (typeof result !== 'undefined') ? result : '',
  (typeof book   !== 'undefined') ? book   : {},
  (typeof baseUrl !== 'undefined') ? baseUrl : '',
  (typeof page   !== 'undefined') ? page   : 1,
  (typeof key    !== 'undefined') ? key    : '');
return __out;
```

⚠️ 薄壳里**所有宿主变量都要 `typeof` 兜底**（宿主不保证给全）⇒ 缺了也不炸 ⭐⭐⭐
⚠️ `loginUrl` 是**间接 eval**（`(0, eval)(...)`）⇒ 目的是让 `jsLib` 顶层函数**落进全局作用域** ⭐⭐⭐

### ⭐⭐⭐ 规则 2：`jsLib` 顶层符号**在「全局共享」时**必须带前缀

⚠️⚠️ **口径更正（2026-11-23 实测）**：这条是**条件性**的，不是无条件的 ⭐⭐⭐

| 宿主行为 | 需不需要前缀 |
|---|---|
| 每个 op **新建** JSContext（轻阅现状）⇒ 跨源不共享全局 | **不必**（但同一次 eval 内的遮蔽仍在）|
| **单例** WKWebView + **间接 eval** ⇒ 全部进全局且无清理 | **必须** ⭐⭐⭐ |
| 将来改成**共享** JSContext | **必须** ⭐⭐⭐ |

⇒ ⇒ **结论：前缀化是「防御性隔离」**（防撞名、防遮蔽标准全局），**不是修当前 bug** ⇒ 改与不改都能跑 ⭐⭐⭐

⚠️⭐⭐⭐ **真正的雷（2026-11-23 实测）：`jsLib` 与 `loginUrl` 会互相引用** ⭐⭐⭐
⇒ 书山聚合 v6 的 `jsLib` **内部调用了 `loginUrl` 定义的 `icons`** ⇒
⇒ ⇒ **两个域必须用【同一个前缀】** ⇒ 否则 `jsLib` 里的 `icons` 改名后会**调不到** ⇒ **功能坏** ⭐⭐⭐
⇒ ⇒ **两域真顶层重名 = 0**（acorn 实测）⇒ 同前缀**不产生冲突**，
   且「后加载者覆盖」的语义与原始**逐字一致**（`loginUrl` 仍在 `jsLib` 之后）⇒ **行为等价** ⭐⭐⭐

⚠️⭐⭐⭐ **改名前必查：跨域引用**（`jsLib` 里引用 `loginUrl` 的符号，或反之）⭐⭐⭐
⇒ **判据**：用 AST 分别列出两域的**真顶层**声明（⚠️ 正则抓「缩进的 function」会**多算**，
   书山这个源正则算出 47/55 个，AST 真值是 **41/19** 个 ⇒ **别用正则下结论**）⭐⭐⭐

**正确写法**：

### ⭐⭐⭐ 规则 4：**要改名就用 AST，别用正则**（2026-11-23 实证）

⚠️⚠️ **正则改 JS 的三个已踩的坑**（书山聚合 v6 适配实证）⭐⭐⭐：

| 坑 | 现象 | 正解 |
|---|---|---|
| **正则抓「缩进的 function」** | 把**嵌套作用域**的函数也算成顶层符号 ⇒ 得出「22 个重名」的**假结论** | 用 AST 的 `Program.body` 只取**真顶层** |
| **`\S` 不匹配全角空格 U+3000** | `[\w\S]*` 匹配不到源里的全角空格 ⇒ 正则**卡住** ⇒ 报「Unexpected character '@' (1:0)」 | 用 `[\w\W]*`（与柴阅 `jsPattern` 对齐）|
| **`{ s }` shorthand** | 直接替换标识符 ⇒ **属性名也变了** ⇒ 语义变 | 展开成 `{ s: newName }` |

⇒ ⇒ **正解**：**acorn 解析 ⇒ AST 上改标识符 ⇒ 按位置区间替换** ⇒
⇒ ⇒ 字符串/注释/正则**天然不受影响**（它们在 AST 里不是 Identifier）⭐⭐⭐
⇒ ⇒ **门禁要配「引用计数守恒」**：改名后每个符号的引用点数 **== 原始源同名的引用点数**
⇒ ⇒ 这一条能抓出「改了定义没改引用」的真漏改（本次就抓到 1 处）⭐⭐⭐
⇒ ⇒ ⚠️ **还要注意「非 JS 字段」别误改**（`{{…}}` 模板 / CSS 选择器 / JSONPath / 正则）
⇒ ⇒ ⇒ 比如 `ruleSearch.lastChapter` = `{{$.source}} · {{…}}` ⇒ **不是 JS** ⇒ 不能当 JS 解析 ⭐⭐⭐

### ⭐⭐⭐ 规则 3：**三套变量，各管各的**（混用会静默互相覆盖）

| 槽 | API | 装什么 |
|---|---|---|
| **站方变量**（一整串）| `source.getVariable()` / `setVariable(str)` | 平台 / 频道 / 排序 / 线路 / 模式（`NH_D`）|
| **书源变量**（map）| `source.get(k)` / `put(k,v)` | 令牌 / CK / 线路名 / 标记 / 诊断 |
| **登录信息** | `source.getLoginInfoMap()` / `putLoginInfo` | 账号 / 密码 / 令牌 / JWT |

⚠️ **典型症状**：把令牌写进站方变量那一格 ⇒ 把平台/筛选状态冲掉 ⇒ **登录一次发现页筛选被重置** ⭐⭐⭐

## 2. 发现页（`exploreUrl` / `ruleExplore`）

### 2.1 `exploreUrl` 返回什么

一段 **JSON 数组字符串**，元素两类：

```jsonc
// 分类（可点 ⇒ 请求 url）
{ "title": "👨完结榜·全部", "url": "http://…/discovedata?type=4&page={{page}}", "style": {…} }

// 筛选栏（点不 ⇒ 改变量）
{ "title": "平台", "type": "select", "chars": ["书旗","番茄"], "default": "书旗",
  "action": "(function(){ … })()", "style": {…} }
```

⚠️ **铁律**：不能有顶层 `return`；**末行表达式即返回值**；只返回 JSON 数组字符串 ⭐⭐⭐

### 2.2 宿主怎么分「分类」与「筛选栏」（**只看 `type`**）

| 站方返回 | 判定 | 去处 |
|---|---|---|
| `type` 缺省或 `"url"`，`url` **非空** | 分类 | `kinds` |
| `type` 缺省或 `"url"`，`url` **为空** | **组标题**（装饰行）| 只更新后续项的 `group` |
| `type != "url"`（`select`/`toggle`/`button`）| **筛选栏** | `filters` |

⚠️⚠️ **顺序必须是「先看 type，再判组标题」** ⇒ 否则「`url` 为空但 `type:"select"`」的筛选项**会被当组标题扔掉** ⇒ **那个源就没有筛选栏** ⭐⭐⭐

### ⭐⭐⭐ 2.2b **「发现页空」先分清：是适配坏了，还是站方状态**（2026-11-23 实证）

⚠️⚠️ **站方自己的标题就是判据**（比推理可靠）⭐⭐⭐：

| 站方返回的标题 | 含义 | 谁的责任 |
|---|---|---|
| 分类项**有** url | 正常 | — |
| `【XX】暂无发现页数据` | 站方 API **没返回分类**（没选源 / 该源当下无数据）| **站方状态** ⭐⭐⭐ |
| `发现页加载失败，请检查服务器/登录` | 站方服务器/登录不可用 | **站方状态** |
| `exploreUrl` **抛异常**（分类项为 0）| 脚本本身炸了（真问题）| **适配/源** ⭐⭐⭐ |

⭐⭐⭐ **站方的发现页可能是「没有 URL 分类，只有 select 筛选」的形态** ⭐⭐⭐
⇒ 例：书山聚合 v6 的 8 个分类项里，**性别 / 模式 / 源站** 都是 `type:"select"` ⭐⭐⭐
⇒ ⇒ **这类源靠「筛选栏切换状态」出内容**，不靠点 URL 分类
⇒ ⇒ **宿主必须支持 `type != "url"` 的项当筛选项**（§2.2）⇒ 否则这个源的发现页**永远是空的** ⭐⭐⭐

⚠️ **站方的分类 url 常常是「URL + 选项」的 POST 形态**（例）：
```
https://host/api/discover/books,{"method":"POST","body":"{...}"}
```
⇒ ⇒ 宿主要能吃 **`url,{json}` 后缀**（§8 记忆条目）⭐⭐⭐

### 2.3 筛选 action 契约（**五步，缺一不可**）

```js
(function(){
  var c = {}; try { c = JSON.parse(source.getVariable() || '{}'); } catch (e) {}
  var v = infoMap['平台'];                                  // ① 取用户选的值
  var m = {"番茄":"番茄","七猫":"七猫"};                       // ② 值映射（可省）
  var nv = (v!==null && v!==undefined && m[v]!==undefined) ? m[v] : '默认';
  c['src'] = nv;                                            // ③ 写站方变量整串
  try { source.setVariable(JSON.stringify(c)); } catch (e) {}
  try { infoMap.put('平台', nv); } catch (e) {}               // ④ 回写下拉框（不回写 = 下拉不重绘）⭐
  try { java.refreshExplore(); } catch (e) {}                 // ⑤ 刷新发现页
})()
```

⚠️⭐⭐⭐ **键名 ≠ 筛选标题**（「平台」写的是 `src`、「📚类型」写的是 `kind`）⇒
⇒ **宿主不能猜键名** ⇒ **正确做法是让站方 action 自己写**（它知道该写哪个键）⇒
⇒ 宿主只负责：① 传 `infoMap` ② 执行 action ③ 缓存失效 ⭐⭐⭐

### 2.4 站方变量与「下拉框自愈」

站方常在 exploreUrl 开头做「下拉框显示值 ↔ 源变量实际值」的双向同步（用一次性标记 `nhPlatSwitch`）⇒
⇒ **别让宿主把站方变量整格覆盖** ⇒ 只改用户改的那一项 ⭐⭐⭐

### 2.5 `ruleExplore` 缺失 ⇒ 引擎会兜底

柴阅的 `BookListParser`：**`exploreRule.bookList` 为空 ⇒ 自动改用 `searchRule`** ⭐⭐⭐
⇒ 所以「源没写 `ruleExplore`」**本身不会**导致 0 本 ⇒
⇒ 但**建议补上**（避免依赖兜底，也避免搜索页与发现页结构不同）

### 2.6 线路变量（`server` / `jmHost` / `host`）

ⓘ 很多聚合源有**多线路**，站方把「当前线路」写在**书源变量**里。

⚠️⚠️ **实测坑**：用户点了「一键获取线路」⇒ 站方测速后写入一条**已挂**的线路 ⇒
⇒ 发现页请求那条 ⇒ **连不上** ⇒ **书单 0 本**（而主站是好的）⭐⭐⭐

⇒ 宿主已做**失败自愈**：0 本 ⇒ 备份线路变量 ⇒ 清掉（站方回落默认主站）⇒ 重试一次 ⇒ 仍失败则恢复 ⭐⭐⭐

## 3. 搜索 / 详情 / 目录 / 正文

| 规则 | 要点 |
|---|---|
| `ruleSearch.bookList` | CSS 选择器（**逗号 = 并集**：`li.jm-card,li.jm-vcard`）|
| `ruleSearch.bookUrl` | **Legado 扩展语法 `class@attr`**（柴阅**支持**）例：`a.jm-card__cover@href` |
| `ruleSearch.coverUrl` | 常见写法 `@js:`（从 `data-src` 取真图）|
| `ruleBookInfo` | 各字段独立求值；⚠️ **别共用一个上下文** ⇒ 各自薄壳 |
| `ruleToc.chapterUrl` | ⚠️ **为空 ⇒ 章节被丢** |
| `ruleContent.content` | 需 `useWebView` ⇒ **宿主必须实现渲染委托**（否则正文空）⭐⭐⭐ |

⚠️ **`result` 绑 JSON 对象时**：`String(result)` 必须回到**原始 JSON 文本**
⇒ 站方常写 `JSON.parse(String(result))` ⇒ 若宿主把 `result` 绑成裸对象 ⇒ `String(result)` = `[object Object]` ⇒ **整片字段为空** ⭐⭐⭐

## 4. 登录（`loginUi` / `loginUrl`）

### 4.1 登录面板有**三种动作**（都要支持）

| # | 动作 | 宿主调用 | 作用 |
|---|---|---|---|
| ① | **行按钮** | `runLoginAction(action, formData:)` | 跑 `loginJs + action` |
| ② | **主「登录」按钮** | **`login(formData:)`** | **跑站方 `loginUrl` + `login()`** ⇒ **「点进去直接进网站」** ⭐⭐⭐ |
| ③ | **「退出登录」** | `runLoginAction(logoutAction)` | 找行里 `action` 含 `logout` 的那个 ⭐⭐⭐ |

⚠️ 缺 ② ⇒ **站方的登录脚本压根没跑** ⇒ 有些书源的登录「点了完全没反应」⭐⭐⭐

### 4.2 `loginUi` 条目的字段

```jsonc
{
  "name": "jmModeN",                     // ⚠️ 技术名
  "viewName": "jmModeLabel('漫画')",       // ★ 人话名（**表达式**）
  "type": "button",                       // text / password / button / toggle / select
  "action": "jmSetMode(java,'漫画')",       // ★ 按钮动作
  "chars": ["…"], "default": "…"
}
```

⭐⭐⭐ **适配要点**：
1. **`name` 是技术名** ⇒ 用户看到 `jmModeN` ⇒ ⇒ **宿主优先用 `viewName`**（求值后）⭐⭐⭐
2. **`viewName` 是表达式** ⇒ 需要**引擎求值**；**字面量**（`'🌐 发布页地址'`）直接剥引号用 ⭐⭐⭐
3. 批量求值时**表达式要转成 JS 字符串字面量再 eval** ⇒ 数组里放裸表达式会「一条炸全炸」⭐⭐⭐

### 4.3 ⭐⭐⭐ **`loginUrl` 里的函数库必须能被 action 调到**

站方常把 `login()` / `jmSetMode()` 等**定义在 `loginUrl`**（注释写「V1 静态 loginUi 的 action 函数库」）。

⇒ 宿主执行 action 时**不会先跑 `loginUrl`**（柴阅的 `runLoginAction` 是 `loginJs + action` 拼着跑 ⇒ 纯 JS 的 `loginUrl` **会被跑** ✔）
⇒ 但若站方的 `loginUrl` 是 **`@js:` 薄壳** ⇒ 引擎会剥壳后拼上 ✔
⇒ ⚠️ **若 action 依赖的函数既不在 `loginUrl` 也不在 `jsLib`** ⇒ ReferenceError ⇒ 静默失败 ⭐⭐⭐

⇒ **最稳做法**：把 action 依赖的函数**搬进 `jsLib` 顶层**（本项目的适配就是这么做的）⭐⭐⭐

## 5. 宿主提供什么、书源要配合什么

| 宿主能力 | 书源侧的配合 |
|---|---|
| 注入 `infoMap`（筛选当前值）| action 读 `infoMap['标题']` |
| 执行 action / 登录脚本 | action 依赖的函数必须在 `loginUrl` 或 `jsLib` |
| 内嵌浏览器（`java.startBrowser`）| 需要读回 Cookie 的登录**必须**用内嵌浏览器（跳系统 Safari ⇒ Cookie 读不回来 ⇒ 登录白搭）⭐⭐⭐ |
| 后台 WebView 渲染（`useWebView`）| 需要 JS 渲染的正文才能出内容 |
| 验证码输入 | 站方调 `java.getVerificationCode` |
| Cookie 同步 | 站方读 `cookie.getCookie` |

## 6. 适配自检清单（出包前逐条过）

- [ ] `exploreUrl` 求值 ⇒ **分类数正常**（> 0）
- [ ] `exploreUrl` 求值 ⇒ **筛选项数 > 0**（0 ⇒ 检查站方有没有输出 `type != "url"` 的项）
- [ ] 每个筛选 action 单测：改值 ⇒ 站方变量对应键变了 ⇒ `infoMap` 回写了 ⇒ `refreshExplore` 调了
- [ ] 切平台 ⇒ **分类 URL 里的平台参数变了**（不是缓存里的旧值）
- [ ] `ruleExplore` 有 `bookList`（或确认引擎的 `searchRule` 兜底可用）
- [ ] `ruleSearch.bookList` 在真实 HTML 上**命中**（拉一次真实页面验，别只看源码）
- [ ] `ruleToc.chapterUrl` 非空（空 ⇒ 章节被丢）
- [ ] 需要 JS 渲染的正文 ⇒ `useWebView` ⇒ 宿主渲染委托已接
- [ ] 未解锁 ⇒ 站方**主动交白卷**（不报错）；解锁后出分类
- [ ] 登录按钮 ⇒ 浏览器能开 ⇒ 登完 Cookie/token 读得回来
- [ ] 站方 action 依赖的函数 ⇒ 都在 `loginUrl` 或 `jsLib` 里（否则静默失败）
- [ ] `jsLib` 顶层符号都带前缀
- [ ] 变量分三套 ⇒ 没混写
- [ ] 构建器**连跑两次 ⇒ 输出字节一致**（幂等）

## 7. 常见的「静默失效」症状 → 对应的适配点

| 症状 | 最可能的原因 |
|---|---|
| 发现页「0 个分类」| `exploreUrl` 求值抛错（薄壳没 `typeof` 兜底）/ 站方门禁未解锁 |
| 有分类但**没有筛选栏** | 宿主把「`url` 为空 + `type:"select"`」当组标题扔了（§2.2 顺序）|
| 筛选点了没反应 | 宿主没传 `infoMap` / action 的函数不在作用域 |
| 书单 0 本（分类有）| `ruleExplore` 没规则且 `ruleSearch` 兜底也不匹配 / **线路变量指向已挂线路**（§2.6）|
| 详情字段整片为空 | `result` 是裸对象 ⇒ `String(result)` = `[object Object]`（§3）|
| 目录 0 章 | `ruleToc.chapterUrl` 为空 |
| 正文空白 | `useWebView` 但宿主没实现渲染委托 |
| 登录点了没反应 | 缺「主登录按钮」那条路 / action 依赖的函数不在作用域（§4）|
| 登录完还是未登录 | 走了系统浏览器（Cookie 读不回来）⇒ 必须是内嵌浏览器（§5）|
| 换台后筛选被重置 | 令牌写进了站方变量那一格（§1 规则 3）|
| 发现页只有几个按钮、**没有分类也没筛选** | 站方的分类项 **`type != "url"`**（如 `select`）⇒ 被当组标题扔了（§2.2）|
| 发现页标题显示「暂无发现页数据」| **站方状态**（没选源 / 该源无数据）⇒ 先点「📡源站选择」（§2.2b）|
