## 一、你反馈的问题：根因找到了（**读代码 + 直连站方实测**得出，不是猜的）

> 真机截图：书山聚合 v6 的**发现页只剩「我的书架（全部）」一项** + toast「**Token 格式错误**」

### ⭐⭐⭐⭐⭐ 第一步：我把站方的「报错判定表」实测出来了

站方主域名在沙盒连不上，但它的**备用线路能直连** ⇒ 我打了一组对照请求，把站方的判定顺序整个摸清：

| 我们发出去的 token | 站方回话 |
|---|---|
| 缺失 / 空 | 非法请求，请先登录 |
| **不是合法 base64（带引号 / 9 字符 / 17 字符…）** | **Token 格式错误** ⭐⭐⭐ |
| 是 base64、但明文长度不对 | Token 长度不正确 |
| 是 base64、长度也对（库里没有 / 签名不符 / 时间戳过期） | Token 无效或已失效，请重新登录 |
| 缺 `x-novel-deviceid` | 缺少验证或非法设备 ID |

⇒ **「Token 格式错误」只可能意味着一件事：我们发出去的 token 根本不是 base64。** ⭐⭐⭐
⇒ 顺带实测出合法 token 的形态 = **12 字节明文 ⇒ 16 字符 base64**。

### ⭐⭐⭐⭐⭐ 第二步：真引擎探针证明「引擎这一侧是好的」

我加了一个探针（macOS CI 真引擎 + 真源 + 真站方），逐环取证：

```
[③] source.putLoginHeader 写入 → 宿主槽落盘值：len=16 逐字相同 ✅
[④] JS 侧 typeof = string ✅ / String(source.getLoginHeader()) 逐字相同 ✅
[⑤] 站方 ssh_buildHeaders 的 x-novel-token：len=16 逐字相同 ✅
[⑥] 「重启」后（全新 WebBook + 同一 store）：token 还在、逐字相同 ✅
[⑦] 真打站方 /api/discover → 「Token 无效或已失效」 ✅（形态/长度/签名全过）
```

⇒ **引擎侧整条管道（写入 → 落盘 → JS 读取 → 拼请求头 → 重启往返 → 站方校验）全部正常** ⭐⭐⭐
⇒ ⇒ **坏的不是引擎 ⇒ 只能是「槽里的值本身被写坏了」。**

### ⭐⭐⭐⭐⭐ 第三步：找到了写坏它的那个写入点

**两个用途在抢同一个存储槽**（`loginHeader` / `sourceheader.<源URL>`）：

| 谁在写 | 写的是什么 | 什么时候写 |
|---|---|---|
| **站方**（书山聚合） | `source.putLoginHeader(token)` ⇒ **站方自己的 token**（裸 base64） | 你点「⭕账号登录」时 |
| **宿主 UI**（🍅番茄 sessionid 兜底） | `setLoginHeader("Cookie: sessionid=…")` | **每个登录动作结束的 `defer` 里**都跑 ⭐⭐⭐ |

⇒ **你点完登录，站方刚把 token 写进去，宿主紧接着就把整槽改成了 `"Cookie: sessionid=…"`** 💥
⇒ ⇒ 站方下一次请求把这整串当 token 发出去 ⇒ ⇒ **站方解不出 base64 ⇒ 「Token 格式错误」** ⭐⭐⭐

**你的截图里那个「🍅番茄 sessionid」框正好是「已保存」状态 ⇒ 完全吻合。**

### ⭐⭐⭐ 而且那个写法**本来就是纯破坏、零收益**

柴阅引擎注入 loginHeader 时只认 **JSON 形态**（`LenientJSON.stringMap`）⇒ `"Cookie: …"` 这种形态**根本注入不了请求头** ⇒ 它既没帮上番茄，又把站方的 token 冲掉了。

## 二、这版改了什么

### ① 番茄兜底不再写站方 token 的槽 ⭐⭐⭐
番茄 sessionid 改走**站方真正读的两条路**：
- `source.getLoginInfoMap()['手动填写番茄token(可不填)']`（站方 jsLib 直接读）
- **真 cookie**（站方主路径就是 `cookie.getCookie('fanqienovel.com')`）

### ② ⭐⭐⭐ 每个 op 自愈 ⇒ **你的设备不用重装源、不用重登**
`SourceVariables.clearLegacyCookieLoginHeader` 会把以 `"Cookie: "` 开头的旧值清掉（**只有宿主自己那种形态**；站方 token 是裸 base64，绝不会被误清）⇒ 你现在这台手机上被污染的槽会被自动修好。

### ③ ⭐⭐⭐ 补上了一个「payload 带了但没人读」的洞
宿主每个 op 都在 payload 里带 `cookieSnapshot`，但**引擎压根没消费它** ⇒ 站方 `cookie.getCookie('fanqienovel.com')` **永远是空** ⇒ 番茄链路缺另一半 ⇒ 现在每个 op 都把宿主 cookie 灌进引擎的 cookie 罐。

### ④ 观测：以后这类问题**一眼就能定位**
- **引擎的日志接进 App 日志面板**（以前引擎的 `ajax(...) error`、`loginUi 脚本出错` 全都丢了，看不见）
- 每次发请求会打印**真实请求头**（头名 + 值长度 + **是否带引号**，**不打印内容**）
- 登录后会打印 **token 指纹**（长度 / 是否 base64 / 是否带引号）⇒ 不泄露凭据，但一眼能分清「存坏了」还是「读坏了」
