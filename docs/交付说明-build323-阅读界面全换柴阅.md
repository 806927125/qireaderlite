## 3. ⭐⭐⭐ 顺手修了一个真 bug：**正文左边距根本没生效**

**你截图里就能看出来**：第二行「子。」从 **x=0** 开始（顶到屏幕左边缘），而右边空着 44pt ⇒ 整块正文**偏左 22pt**。

- 根因：分页路径的绘制原点是 `CGPoint(x: 0, y: headerHeight)` ⇒ **左边距只体现在页容器宽度上，没体现在绘制位置上**。
- 修法：chrome 带 `horizontalMargin`（22）⇒ 绘制原点 x = 边距 ⇒ **页眉 / 页脚 / 章节号装饰一起缩进** ⇒ 左右对称。

## 6. ⭐⭐⭐ 这轮踩的坑与加固（都写进门禁/脚本了）

1. **「按字符串切代码」切掉了 `ReaderSession.attach()`**
   ⇒ 切完语法合法 ⇒ **只有 Xcode 编译才炸** ⇒ 白烧一轮 CI
   ⇒ ⇒ 新增 **API 清单门禁**：钉住 4 个文件的公开成员（已做变异对照：删 `attach()` ⇒ 红并点名 ⇒ 复原 ⇒ 绿）。
2. **推送到 GitHub 的三个血坑**（`/workspace/tools/git_push_api.py` 已加固）
   - Trees API 的 `content` 必须是**原始文本**（base64 是 Contents API 的规矩）
   - **重命名必须删旧路径**（`git show --name-only` 只给新路径 ⇒ 旧文件留在远端 ⇒ `ReaderTheme` 重复声明 ⇒ CI 一堆 ambiguous 错）
   - **「远端有、本地没有」的判据必须看磁盘**：用 `git ls-files` 会把「用 API 推的、没被 git 跟踪」的文件全删；遍历时写 `startswith(".git")` 会把 `.github` 误伤（CI workflow 消失 ⇒ CI 根本不跑）
   ⇒ ⇒ 现在推送器**推后全量核对**（远端 == 本地跟踪集），不一致就报错退出。
3. **沙盒语法门禁**（`swiftc -parse`，15 秒 / 68 个文件）本轮继续有效：语法错在沙盒就抓到了，没再为语法错烧 CI。
