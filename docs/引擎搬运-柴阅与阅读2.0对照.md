# 引擎「能搬过来吗」的结论（2026-11-18）

问题：用户给了 **阅读2.0.ipa** 与 **柴阅 Chaiyue-0.1.0.ipa**，问「它的引擎你能搬过来吗」。

## 一、两个参照物的引擎形态（实测）

### 阅读2.0（YueduReader，闭源）
- `ruleEngine.js`（52KB，纯 JS）+ `ModernRuleEngine.swift`（Swift 主体）
- 形态 = **Swift 宿主 + WebView 内规则求值 + 原生只过字符串**
- ⚠️ **闭源** ⇒ 只能学架构，代码不能拷（否则侵权）

### 柴阅（Chaiyue 0.1.0，com.linchengbo.chaiyue）
- 二进制里 **Sextant 1849 处引用**（+ mangled 符号 `SextantE` / `SextantAAC`）
- 另有 `AnalyzeRule.swift` / `AnalyzeByJSONPath.swift` / `AnalyzeByJSoup.swift` / `JSContext` / `WKWebView`
- ⇒ **柴阅的引擎 = 栖阅同构**：**Sextant（MIT）+ 自研 AnalyzeRule/AnalyzeUrl/JavaBridge + JSC/JSContextPool + WKWebView**
- ⇒ ⭐⭐⭐ **Sextant 是 MIT**（KittyMac/Sextant，依赖 Hitch/Spanker/Chronometer 也都 MIT）
  ⇒ **引擎可以合法搬** ⭐⭐⭐

## 二、许可边界（决定「能搬什么」）

| 来源 | 许可 | 能搬？ |
|---|---|---|
| **Sextant / Hitch / Spanker**（KittyMac） | **MIT**（可商用、无 copyleft） | ✅ **直接搬** |
| 栖阅 / 柴阅 的 `AnalyzeRule` / `AnalyzeUrl` / `JavaBridge` | 闭源 | ⚠️ 只能**按语义重写**（我们有反推材料：topic `qiyue-reverse-engineering`） |
| 阅读2.0 的 `ruleEngine.js` | 闭源 | ❌ 不拷；只学架构 |
| 橘阅 Juyue | **GPL-3.0** | ⚠️ **只可读不可拷**（会污染闭源 App 的分发许可） |

## 三、真正缺的那一层（不是整个引擎）

轻阅现状：
- `legado-engine`（Swift）：`JSONPath.swift` + `JSONFilter.swift` = **手写的「Sextant 风格」子集**
  （注释自陈：照 125 源真实用法整理 ⇒ 子集）
- 轻阅 App 侧：`Resources/engine/sextant-filter.js`（536 行）= **栖阅同款过滤表达式的 JS 版**（build170 落的）
  ⇒ 即：**那套语义在轻阅里只有 WebView 里的 JS 版**；自研 Swift 引擎只有子集

⇒ ⭐⭐⭐ **缺口精确定位**：子集之外的过滤表达式 ⇒ **整条路径作废** ⇒ 字段全空 ⇒ 症状离根因极远。

## 四、本轮已做（engine 分支 `feat/sextant-jsonpath`，commit `bc53d68`）

1. `Vendor/SextantKit/`：**本地 vendored** 的 MIT 包（Sextant / Hitch / Spanker，80 个 Swift 文件）
   - **本地 path 依赖 ⇒ 不联网** ⇒ 沙盒 / Linux 门禁离线也能编 ⭐
   - **三个包保持独立模块** ⇒ ⚠️ 不能同模块（`Hitch.ValueType` 与 `Spanker.ValueType` 定义不同 ⇒ 同模块会 invalid redeclaration）⭐⭐⭐
   - 唯一源码改动 = 删掉 `Sextant.swift` 里**未使用**的 `import Chronometer`（1 行）
2. `LegadoCore/Evaluator/SextantFallback.swift`：新兜底层
3. `JSONPath.select`：**手写优先（行为零变化）** ⇒ 解析不了 / 带过滤表达式却算空 ⇒ 才用 Sextant
   ⇒ 之前是 nil（= 空）⇒ 现在最多「有值」⇒ **严格优于之前**，不存在把对的改错 ⭐⭐⭐
4. `Tests/LegadoCoreTests/SextantFallbackTests.swift`：6 项（含「手写确实解析不了」的前置断言
   ⇒ 否则测的是手写路径 ⇒ 门禁变成平凡通过）
5. 轻阅侧：SPM 依赖 `legado-engine` 的 branch `main` → `feat/sextant-jsonpath`（**1 行**）
   ⇒ 不碰用户在另一窗口自研的 main；回退也是 1 行 ⭐

## 五、还没搬的（下一步候选，按性价比排序）

| 层 | 状态 | 备注 |
|---|---|---|
| JSONPath + 过滤表达式 | ✅ **本轮已搬（MIT）** | |
| `AnalyzeRule`（规则编译：多规则/取值模式/复合规则/尾部 @js:） | ⚠️ 闭源 ⇒ 重写 | 我们的 `legado-engine` 已有等价物，重点是**对拍** |
| `AnalyzeUrl`（URL 规则：占位/选项后缀/编码） | ⚠️ 同上 | 轻阅 `Core/AnalyzeUrl.swift` 已有 ⇒ 对齐语义即可 |
| `JavaBridge`（宿主 API 家族） | ⚠️ 同上 | ⭐ 我们已有 22 个能力 ⇒ 差集门禁补齐 |
| JS 求值运行时 | ⭐ **已有**：轻阅的 `WebViewJSExecutor`（独立进程） | 栖阅用 JSC（进程内）⇒ ⭐ **我们反而更安全**（jetsam） |

⇒ ⭐ **下一步建议**：不是「再搬一层」，而是**用真实书源做新旧双实现对拍** ⇒ 差集 = 缺口清单 ⇒ 按缺口补（这才是记忆里「让真实语料自己指出缺口」的路子）。
