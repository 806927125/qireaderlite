## 补充（2026-11-18 傍晚）：四环全部打通 + 「共同缺口」的真凶

> 上一节记的是「两环 + 两边都空」。本节把**详情 / 目录 / 正文**三环打通，并找到了「两边都空」的**三层根因**。

### 三层根因（**其中两层是探针自己的坑，第三层才是引擎真凶**）

| # | 根因 | 性质 | 表现 |
|---|---|---|---|
| ① | 探针给老引擎的 mock 响应形态错（`{value,status}` 而非 `{ok,code,body}`） | **探针自身的坑** | 正文恒空 ⇒ 字段全空 |
| ② | 探针没把「书籍变量」灌进老引擎（`__variables`）/ 没灌进 Swift 侧的宿主状态快照 | **探针自身的坑** | `nhAuth()` 恒 false ⇒ 交白卷 |
| ③ | ⭐ **老引擎把 `@js:` 规则在正文里提到的第二个 `@js:` 处腰斩** | **产品真凶** | `try{}` 失去 catch ⇒ 规则死 ⇒ 6 个详情字段全空 |

### ③ 的机理（跨项目级通用坑）

站方的 `@js:` 规则正文里有这种注释：

```js
// 命中就覆盖 out（不 return —— @js: 是 evaluateString 语义，顶层 return 会抛）
```

⇒ 老引擎 `rule-analyzer.js` 的 `findJsTail()` 用 `indexOf('@js:', 4)` 找「尾部 JS 后处理」
⇒ **在注释那一处把规则腰斩** ⇒ 腰斩后 `try { … }` 失去 `catch`
⇒ `SyntaxError: Missing catch or finally after try` ⇒ **整条规则死**
⇒ ⇒ **聚合源的 name / author / kind / lastChapter / coverUrl / wordCount 六个字段一起空**
⇒ ⇒ 这就是「轻阅上聚合源详情只有站方原文」的真凶 ⭐⭐⭐

✅ **正确口径**（栖阅 AnalyzeRule 一致、自研引擎 `RuleParser` ②' 一致）：
**`@js:` 前缀 ⇒ 整条规则就是 JS 代码 ⇒ 不取尾部、不按 `||`/`&&` 拆。**

### ⭐ 三条元教训（跨项目）

1. **「两边都空」的差集 = 0 是最危险的假绿** ⇒ 必须配「两边不能都空」的**绝对断言**。
2. **探针必须先自证**：先证明「原始输入真的坏」再下结论（这轮自己造的假象就有 2 处）。
3. **注释里的 `@js:` / 引号 / 花括号会骗过切分器** ⇒ 「规则解析」类实现必须**注释感知**。
