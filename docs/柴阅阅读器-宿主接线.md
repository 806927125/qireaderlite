### ⭐ 三条关键设计

1. **shim 在宿主侧，不在包里**
   柴阅自己的 `LibraryServices` 管书源/书架/替换规则/本地书；轻阅的数据全在轻阅的 `SourceStore` / `LibraryStore` 里。
   ⇒ 用两套书库会打架 ⇒ **包侧只留门面协议 `ChaiyueReaderLibrary`**，实现放宿主
   （`ChaiyueHostLibrary`）⇒ 轻阅仍是唯一主数据源。

2. **会话必须缓存（一本书一个）**
   柴阅的 `ReaderContainer` 启动时会调 `app.library.readerSession(for: launch.book)`。
   ⇒ 宿主若每次新建会话 ⇒ 界面与宿主持**两个对象** ⇒ 进度永远回写不进去 ⇒
   ⇒ `ChaiyueHostLibrary` 用 `sessions[book.bookUrl]` 缓存 ⇒ **界面与宿主共用一份**。

3. **目录不重复请求站方**
   详情页已经取过一次目录 ⇒ 宿主把它**预写进柴阅的 `ChapterStore`**
   ⇒ `ReaderSession.open()` 命中缓存 ⇒ 零额外请求、两边目录一致。

### ⭐ 命名纪律（撞名）

宿主 App 自己有 `Book` / `Chapter` / `BookSource`；`import ChaiyueReader` 会把柴阅的**同名类型**带进来。

- 柴阅的模型 ⇒ 一律写 `LegadoEngineHost.BookModel` / `.ChapterModel` / `.Source`（`LegadoEngine` 模块再导出一次 ⇒ 名字唯一）
- 宿主的模型 ⇒ 一律写 `QiBook` / `QiChapter` / `QiBookSource`
  （定义在 `ChaiyueReaderAdapter.swift`，**该文件故意不 import ChaiyueReader** ⇒ 解析到的一定是宿主自己的）

### ⭐ 四、下标口径（两套，别搞混）

| | 口径 | 谁在用 |
|---|---|---|
| 轻阅 `LibraryItem.lastChapterIndex` | **正章节下标**（过滤掉卷） | 书架显示「在读第 N 章」、老阅读器存的位置 |
| 柴阅 `Book.durChapterIndex` / `session.position.chapterIndex` | **整表下标**（含卷） | 柴阅阅读会话 |

⇒ 宿主侧用 `plainToWhole` / `wholeToPlain` 两张换算表来回换 ⭐⭐⭐
（`ChaiyueReaderHost` 内）⇒ 不换算的话：起读位置会跳章、书架上章号会乱 ⭐⭐⭐

### ⭐ 五、进度回写（双向）

1. **进阅读器**：轻阅书库 → 柴阅书架仓（镜像）。
   ⚠️ **柴阅书架仓里已有的进度不许被轻阅的旧值覆盖** ⇒ 否则 App 被杀（没回写）时**阅读位置会丢** ⭐⭐⭐
2. **出阅读器**：柴阅书架仓 → 轻阅书库（`writeBackProgress`）
   ⚠️ 位置取**会话的实时位置**（`session.position.chapterIndex`），不是书架仓的副本 ⭐⭐⭐
3. **「开始阅读」跟着进度走**（`BookDetailView.resumeChapter`）⭐⭐⭐
   以前固定开第一章 ⇒ 读到第 50 章再点还是从头开始 ⇒ 柴阅是记住进度的，这里也改 ⭐⭐⭐
