## 结构

```
LegadoEngine/Sources/
├── ChaiyueModels/   柴阅的 ReaderModels（13 文件）—— 模型层
├── ChaiyueEngine/   柴阅的 RuleEngine（34 文件）+ 我们的移植补丁
│   ├── Compat/ChaiyueStoreMapping.swift  柴阅键 ⇄ 轻阅槽的映射（纯逻辑）
│   ├── Compat/LegadoPublicAPI.swift       给宿主开的公开出口
│   └── JS/JSStubs.swift                   Linux 沙盒桩（eval 如实抛错）
└── LegadoEngine/    我们的适配层
    ├── LegadoEngineHost.swift   宿主契约（typealias 全部指向柴阅）
    └── ChaiyueKeyValueStore.swift  柴阅 KeyValueStore ⇒ 轻阅 UserDefaults 槽
```

宿主侧（`QiReaderLite/Core/`，**UI 零改动**）：
- `LegadoEngineBackend.swift` ⇒ 每条主链改走柴阅的 `WebBook`
- `ChaiyueRuntime.swift` ⇒ 存储适配 + 引擎环境
- `ChaiyueKindsAdapter.swift` ⇒ 柴阅 `ExploreKind` ⇒ 轻阅 UI 的 `kinds`/`filters`

## ⭐⭐⭐ 本轮沉淀

1. ⭐⭐⭐ **SwiftPM 的 build plan（`.build/*.yaml`）不会自动纳入新加的 `.swift` 文件**
   ⇒ 新文件根本没被编译 ⇒ 报「cannot find X in scope」⇒ **看起来像代码写错，其实是 plan 过期（假红）**
   ⇒ 正解：编译前 `rm -f .build/*.yaml`（已固化进 `linux-compile-gate.sh`）⭐⭐⭐
2. ⭐⭐⭐ **Linux 沙盒编不到的代码 ⇒ 必须有静态门禁兜底**
   ⇒ 本轮真实事故：柴阅的 `Digests` 拆文件时漏了 `import CommonCrypto` ⇒ Linux 全绿 ⇒ CI 才报 ⭐⭐⭐
   ⇒ 正解：`conditional-import-gate`（用了某框架的符号 ⇒ 该文件必须 import 它）⭐⭐⭐
3. ⭐⭐⭐ **同一模块里「跨文件同名」不一定是撞名** ⇒ 若两份定义处于**互斥的条件编译**（`canImport(X)` vs `!canImport(X)`）⇒ 合法
   ⇒ 正解：门禁要豁免「条件互斥」的同名（否则会误报）⭐⭐⭐
